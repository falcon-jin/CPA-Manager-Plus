# 认证文件当前页额度刷新设计

## 背景与问题

认证文件页面顶部的“刷新”目前只重新加载认证文件列表、OAuth 排除配置、模型别名和 Codex 检查快照，不会调用认证文件对应提供商的额度接口。

认证文件卡片虽然具备单文件额度请求逻辑，但额度区只在未加载状态下把提示文字作为可点击入口。额度已经成功加载或加载失败后，卡片不会显示明确的“刷新额度”按钮。因此用户无法可靠地重新查询当前额度。

## 目标

- 顶部“刷新”在保留现有数据刷新行为的同时，刷新当前页认证文件的额度。
- 每张支持额度查询的认证文件卡片常驻“刷新额度”按钮。
- 顶部批量刷新与卡片单文件刷新复用同一套状态更新和错误处理逻辑。
- 不改变筛选、排序、分页、紧凑模式和现有 Codex 历史快照展示规则。

## 范围

顶部刷新以用户点击瞬间的 `pageItems` 为准，也就是经过当前筛选、排序和分页后显示在当前页的认证文件。

以下认证文件不发起额度请求：

- 已禁用的认证文件；
- 仅运行时存在的虚拟认证文件；
- 不属于 Antigravity、Claude、Codex、Kimi 或 xAI 的认证文件；
- 同一认证文件已有额度请求正在进行。

紧凑模式隐藏额度详情，但顶部刷新仍然刷新当前页符合条件的认证文件额度。

## 方案选择

采用页面级额度刷新协调器，而不是通过刷新令牌让已挂载卡片自行请求。

刷新令牌方案依赖额度组件已经渲染；紧凑模式下额度组件不会挂载，顶部刷新会失效。页面级协调器直接接收当前页认证文件，无论额度详情是否显示都能执行相同请求，并且能够统一限制并发。

## 组件与职责

### 额度刷新协调器

新增认证文件页面专用的额度刷新 hook。它负责：

- 根据认证文件提供商选择现有额度配置；
- 使用现有额度 store key 和身份作用域读取旧状态；
- 写入 loading、success 或保留旧数据的 failure 状态；
- 防止同一认证文件重复并发请求；
- 为当前页批量刷新提供最多 4 个并发请求的执行入口；
- 单卡刷新时显示现有成功或失败通知，批量刷新时避免逐卡通知风暴。

该 hook 暴露两个入口：单文件刷新和文件集合刷新。两者共享同一个内部刷新函数。

### 认证文件页面

顶部刷新处理函数继续执行现有的认证文件、OAuth 配置和 Codex 快照加载，同时把点击时的当前页 `pageItems` 交给额度刷新协调器。

页面把单文件刷新函数传给每张 `AuthFileCard`。

### 认证文件卡片与额度区

`AuthFileCard` 只负责把单文件刷新回调传入 `AuthFileQuotaSection`。

`AuthFileQuotaSection` 继续负责读取和展示额度状态，但不再自行实现请求和 store 更新。额度区增加常驻“刷新额度”按钮：

- idle、success 和 error 状态均显示按钮；
- loading、页面连接不可用或认证文件禁用时按钮不可点击；
- 按钮使用现有 `auth_files.quota_refresh_single` 和 `auth_files.quota_refresh_hint` 文案；
- 额度内容继续显示现有加载提示、错误内容和进度条。

## 数据流

1. 用户点击顶部“刷新”。
2. 页面保存当前 `pageItems` 快照。
3. 页面并行启动现有页面数据刷新和当前页额度刷新。
4. 额度协调器过滤不符合条件的认证文件，并以最多 4 个并发请求调用各提供商现有 `fetchQuota`。
5. 每个结果按现有配置写回对应 Zustand 额度 store。
6. 卡片订阅 store 后自动显示最新额度。

单卡按钮从第 4 步开始，只处理目标认证文件，并保留现有成功或失败通知。

## 错误处理

- 单个额度请求失败不阻止当前页其他认证文件继续刷新。
- 支持 `buildFailureState` 的提供商保留上一次有效额度数据，并附加本次错误信息和失败时间。
- 其他提供商使用现有 `buildErrorState`。
- 顶部批量刷新不产生逐卡成功通知；失败状态直接显示在对应卡片中。
- 页面数据刷新和额度刷新互不取消，任一额度失败不会破坏认证文件列表刷新。

## 测试计划

先添加失败的回归测试，再实现代码：

- 已有成功额度时，卡片仍显示“刷新额度”按钮。
- 点击单卡按钮调用正确提供商的额度请求并更新 store。
- 单卡刷新失败时保留旧 Codex 额度数据。
- 顶部刷新只请求当前页认证文件，不请求其他分页中的认证文件。
- 顶部刷新跳过禁用、虚拟和不支持额度查询的认证文件。
- 紧凑模式下顶部刷新仍然请求当前页额度。
- 批量刷新遵守并发限制且单项失败不阻止其他项完成。

完成后运行认证文件相关 Vitest、前端类型检查、`git diff --check`，并根据结果决定是否需要扩大到完整前端测试。

## 非目标

- 不改变独立“配额管理”页面。
- 不新增后端额度接口。
- 不自动刷新非当前页认证文件。
- 不修改认证文件筛选和分页语义。
